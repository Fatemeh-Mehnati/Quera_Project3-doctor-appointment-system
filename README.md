# سیستم نوبت‌دهی آنلاین پزشکان

سامانه‌ای برای مدیریت و رزرو نوبت ویزیت پزشکان توسط بیماران، شامل جستجوی پزشک، رزرو بازه زمانی، پرداخت از کیف پول و ثبت نظر و امتیاز.

پروژه سوم بوت‌کمپ کوئرا — توسعه‌یافته با Django و معماری MVT.

---

## امکانات

- ثبت‌نام و ورود با ایمیل و کد یک‌بارمصرف (OTP)
- جستجوی پزشک بر اساس نام یا تخصص
- مشاهده بازه‌های زمانی خالی هر پزشک
- رزرو نوبت و پرداخت هزینه ویزیت از کیف پول
- ارسال ایمیل تاییدیه رزرو
- ثبت نظر و امتیاز برای پزشکان ویزیت‌شده
- پنل مدیریت برای افزودن پزشک، تخصص، بازه زمانی و تعیین هزینه

## راه‌اندازی محلی

### پیش‌نیازها

- Python 3.13 یا بالاتر
- Git
- pip

### مراحل

مخزن را کلون کنید:

```bash
git clone https://github.com/Fatemeh-Mehnati/Quera_Project3-doctor-appointment-system.git
cd Quera_Project3-doctor-appointment-system
```

محیط مجازی بسازید و فعالش کنید:

```bash
python3 -m venv venv
source venv/bin/activate        # macOS و Linux
venv\Scripts\activate           # Windows
```

وابستگی‌ها را نصب کنید:

```bash
pip install -r requirements.txt
```

فایل تنظیمات محیطی را بسازید:

```bash
cp .env.example .env
```

سپس `.env` را باز کنید و مقادیر را پر کنید (توضیح هر متغیر در بخش «متغیرهای محیطی»).

پایگاه داده را بسازید:

```bash
python manage.py migrate
```

کاربر ادمین بسازید:

```bash
python manage.py createsuperuser
```

سرور را اجرا کنید:

```bash
python manage.py runserver
```

پروژه روی `http://127.0.0.1:8000` بالا می‌آید و پنل ادمین روی `http://127.0.0.1:8000/admin`.

## متغیرهای محیطی

همه تنظیمات وابسته به محیط از فایل `.env` خوانده می‌شوند. نمونه‌اش در `.env.example` هست.

| متغیر | توضیح | نمونه |
|---|---|---|
| `SECRET_KEY` | کلید محرمانه جنگو | `django-insecure-...` |
| `DEBUG` | حالت دیباگ — در پروداکشن حتماً `False` | `True` |
| `ALLOWED_HOSTS` | دامنه‌های مجاز، جداشده با کاما | `localhost,127.0.0.1` |
| `DB_ENGINE` | موتور پایگاه داده | `django.db.backends.postgresql` |
| `DB_NAME` | نام پایگاه داده | `appointment_db` |
| `DB_USER` | کاربر پایگاه داده | `postgres` |
| `DB_PASSWORD` | رمز پایگاه داده | — |
| `DB_HOST` | میزبان پایگاه داده | `localhost` |
| `DB_PORT` | پورت پایگاه داده | `5432` |
| `EMAIL_BACKEND` | بک‌اند ایمیل | `django.core.mail.backends.console.EmailBackend` |
| `EMAIL_HOST` | سرور SMTP (فقط پروداکشن) | `smtp.gmail.com` |
| `EMAIL_PORT` | پورت SMTP | `587` |
| `EMAIL_HOST_USER` | نام کاربری ایمیل | — |
| `EMAIL_HOST_PASSWORD` | رمز ایمیل | — |
| `OTP_EXPIRY_SECONDS` | مدت اعتبار کد یک‌بارمصرف | `120` |

> در محیط توسعه `EMAIL_BACKEND` را روی `console` بگذارید تا کدهای OTP و ایمیل‌های تاییدیه در ترمینال چاپ شوند و نیازی به سرویس ایمیل واقعی نباشد.

## روند توسعه

پروژه با دو برنچ محافظت‌شده کار می‌کند:

- `main` — نسخه نهایی؛ merge نیازمند ۲ تایید
- `dev` — برنچ کاری اصلی؛ merge نیازمند ۱ تایید

هیچ‌کس مستقیم روی این دو برنچ پوش نمی‌کند. روند کار:

```bash
git checkout dev
git pull
git checkout -b feature/<موضوع>
# کار و کامیت
git push -u origin feature/<موضوع>
```

سپس Pull Request به `dev` باز می‌شود و پس از review و تایید merge می‌گردد.
